# 边界与限制（LIMITS）

## 1. 明确不做的事

| 不做 | 原因 |
|-|-|
| 联网检索并「补全」文献 | 会引入材料外事实，直接违反题目「不新增材料外事实」 |
| 自动判断某句话「必须有引用」并插入 | 插入需要作者意图，自动插入即编造来源；本 Skill 只给**建议清单**（`possible_missing_citations`），不落笔 |
| 改写正文措辞 | 本 Skill 只动引用标记与文末列表，正文文字逐字保留（除标记替换） |
| 合并「极高概率是同篇但没有证据」的条目 | 误合并是无声的数据损坏，宁可 `needs_review` |
| 生成正式案例答案 | 提交物是工具，案例由平台提供 |

## 2. 已知技术边界

| 边界 | 现状 | 影响 |
|-|-|-|
| 引用样式 | 仅内建 GB/T 7714-2015（顺序编码制）与 APA 7 | Vancouver / Chicago / MLA 需扩展 `pk/styles.py` |
| Word 域代码 `{ REF }` | 不支持 | 需先转纯文本 |
| 脚注体例 | 只识别正文内标记，脚注区按普通文本处理 | 脚注型引用需扩展解析 |
| 扫描版 PDF | 需镜像内 `pdftotext` 或 PyMuPDF；且无文本层时不做 OCR | 否则 `partial` 并说明 |
| 论断—文献匹配 | 依赖材料给出摘要/全文 | 无证据文本 → 一律 `evidence_insufficient`，不给假 `supported` |
| 中英跨语言去重 | 依赖 DOI/arXiv 桥梁，或「作者+年+卷/页/刊名」多重佐证 | 只有作者+年时**不合并**，转人工 |
| 上标数字标记 | 仅当正文完全没有 `[n]` 时才启用上标解析 | 混排场景可能漏识别 |
| 超长文献库 | 去重为两两比较（有预筛），O(n²) 最坏 | 数千条以上建议先分库 |
| 作者姓名 | 拉丁与中文姓名启发式切分 | 复姓、`von/de` 前缀、纯缩写名单可能需人工核对 |

## 3. 判定强度的含义

- `info`：证据（如 DOI 已解析），不改变判定。
- `低`：字段间轻微不一致（如不同来源的卷号写法），不影响交付。
- `中`：需要人工确认（DOI 未注册、字段缺失、跨语言存疑合并）→ `needs_review`。
- `高`：不可核验（库外条目、DOI 语法错误、缺题名）→ `fail` / 疑似编造。

**离线与在线不应改变「是否编造」的结论**：断网只降低证据层级（`doi_network: not_checked`），不会把条目从 `ok` 变成 `fail`，也不会把 `fail` 洗成 `ok`。

## 4. 维护

| 项 | 值 |
|-|-|
| 版本 | 1.0.0 |
| 入口 | `scripts/run.py`（CLI）、`scripts/pk/`（模块） |
| 自测 | `python tests/run_tests.py`（20 项） |
| 改动最频繁的位置 | `pk/identity.py`（阈值）、`pk/contract.py`（字段别名）、`pk/styles.py`（体例） |
| 升级契约别名 | 只改 `contract.py` 的 `SYNONYMS`，不动主流程 |
| 升级阈值 | 只改 `identity.compare()`，并用 `tests/` 的 `broken` 案例回归（必须保持 3 合并 / 0 误合并） |

## 5. 出问题时的定位顺序

1. `result.json` → `status` / `status_reason` / `errors`；
2. `run_manifest.json` → 输入指纹、样式来源、是否幂等；
3. `envelope.metrics` → 各计数是否与预期规模一致；
4. `merge_decisions.json` → 具体哪一对判错；
5. 复跑 `--no-network` 排除网络干扰（判定应基本不变，仅 `doi_network` 字段不同）。
